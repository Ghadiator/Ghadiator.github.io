Architecture · Decision committee

Resource cost is a decision constraint, never a substitute for evidence.

Approved sources and primitive Python functions ground the results. An optional Tier-2 AI selector chooses which bounded checks to run; its model usage must be measured. The Proponent, Opponent, CoVe and Judge are separately budgeted, conditional reasoning roles. Resource limits can postpone work, but must never suppress verification or human authority.

01 · Tier 1

Exact checks

Arithmetic and structure: reproducible Python checks, no model call.

02 · Tier 2

Grounded selection

Approved evidence and Python primitives. An enabled AI selector consumes metered model tokens.

03 · Tier 3

Bounded committee

Role calls and CoVe verification are admitted under provider budgets and token windows.

04 · HITL

Safe decision

Human authority persists; missing evidence or exhausted limits defer the decision instead of weakening controls.

Admission

Provider and key quotas, window capacity, and allowed call budgets gate model execution.

Attribution

Input/output tokens, model, provider, role and recorded per-run cost are observable only where telemetry exists.

Recovery

Bounded retries or fallback may restore service. Exhausted limits preserve evidence and hand unresolved work to HITL.

Zero recorded provider tokens in the public reference do not establish production savings. Provider accounting requires authenticated engine telemetry.

Validation workbench · Source controls

Six controls behind a bounded model budget

Restored from the earlier DAiA workbench architecture and adapted to supplier validation. These are capabilities and oversight questions, not measured cost savings or proof that each control fired in the recorded fixtures.

  1. 01

    Avoid unnecessary reasoning

    Tier 1 is deterministic. An enabled Tier-2 selector may still call AI to choose grounded Python checks; only a resolved case bypasses the Tier-3 committee.

  2. 02

    Control proposal attempts

    Bound the number of proposals, role calls and verification attempts before a retry can enter a new budget window.

  3. 03

    Allocate provider capacity

    Inspect available provider/model seats and rotating key-pool capacity. A selected model must be available and admitted.

  4. 04

    Respect rate windows

    Use per-provider request and token windows. A capacity wait is an operational outcome, not a reason to skip verification.

  5. 05

    Constrain retries and fallback

    Use allowed fallback paths and capped recovery. On exhaustion, defer rather than silently make a weaker decision.

  6. 06

    Attribute resource usage

    Track measured input/output tokens, per-role and per-model consumption, cost estimates and wait time from backend-emitted telemetry.

Engineering source: model selection and routing; key pool, cost control, token board and token-story telemetry. Live provider windows and attributable cost require a protected service response; the public static reference does not fabricate those values.
