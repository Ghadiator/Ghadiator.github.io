The hazard log (8)

What was feared, what stops it, and what the control still does not cover. Authored for this runner. Each row carries its control, the test that exercises it, what it still leaves uncovered, and a grading.

  • H1A proposal pairs correct figures with a fabricated account of events.needs 3 · reaches 4
    If it happens
    A reviewer approves on evidence that was never checked, believing the numbers vouch for the story.
    What stops it
    A verified finding is rebuilt from the checked evidence; the proposal's own wording is discarded.
    What it still does not cover
    Only a computed volume variance is admissible. Any other finding type is dropped rather than verified — the runner cannot check it, so it does not carry it.
    Exercised by
    test_verified_finding_is_restated_from_evidence_not_proposal_prose

    severity 3exposure 2controllability 3class structuralfails closed

  • H2Supplier free text instructs the system to approve without review.needs 2 · reaches 4
    If it happens
    An invoice is accepted on the supplier's own say-so.
    What stops it
    Free text never reaches the proposal adapter or the decision; the proposer is handed a revalidated submission with the note removed.
    What it still does not cover
    The instruction-pattern detector is two signatures and is not a comprehensive injection detector. Structural exclusion is what holds, not detection.
    Exercised by
    test_supplier_note_never_reaches_proposal_adapter

    severity 3exposure 1controllability 2class structuralfails closed

  • H3An unauthorised actor records a decision.needs 3 · reaches 2 · gap 1
    If it happens
    A submission is disposed of by someone with no authority to do it, and the record says otherwise.
    What stops it
    An explicit Awaiting_reviewer state plus a reviewer allowlist; an unauthorised resume raises and mutates nothing.
    What it still does not cover
    A reference authorization check against a configured set, not a production identity system, session model or delegation chain.
    Exercised by
    test_gate_prevents_archive_and_unauthorised_decision

    severity 3exposure 1controllability 3class detectivefails closedcapped: The allowlist is a set held by this process. The mechanism — an explicit authorisation check that mutates nothing on failure — transfers to a deployment; the identity behind it does not, and a session or delegation model would have to supply it.

  • H4A hard check failure is waived at the gate.needs 2 · reaches 4
    If it happens
    An invoice that failed arithmetic or contract checks is approved anyway.
    What stops it
    resume() refuses an approval while failures remain; the case must be corrected or rejected.
    What it still does not cover
    Covers this runner's fourteen checks. A check that is not implemented cannot fail, and so cannot block.
    Exercised by
    test_hard_rule_failure_cannot_be_overridden

    severity 3exposure 2controllability 1class structuralfails closed

  • H5The same invoice is submitted and accepted twice.needs 3 · reaches 1 · gap 2
    If it happens
    A duplicate payment downstream.
    What stops it
    The supplier-and-invoice identity is checked against an approved-invoice register before approval is possible.
    What it still does not cover
    The register is an in-memory fixture. A deployment needs a durable, shared one, or the check only sees one process.
    Exercised by
    test_contract_failures_drive_rejection

    severity 2exposure 2controllability 3class detectivefails closedcapped: The register lives in memory for the length of one run. Across two processes — or one restart — it sees nothing, so in a deployment this control is effectively absent until a durable shared register replaces it. This is the widest gap in the log and the first thing an integration has to close.

  • H6A correction quietly replaces the submission it corrects.needs 2 · reaches 2
    If it happens
    The record no longer shows what was originally claimed, so the decision cannot be reconstructed.
    What stops it
    A correction must keep the case and invoice identity and increase its version; earlier events stay in the record and every check runs again.
    What it still does not cover
    Records are held in memory for the run. Durable custody, retention and tamper evidence are integration responsibilities.
    Exercised by
    test_correction_revalidates_and_keeps_original_events

    severity 2exposure 2controllability 2class structuralfails closedcapped: Version enforcement and event retention are ordinary logic and transfer as they are. What does not transfer is durability: records are held for the run, so retention and tamper evidence remain integration responsibilities.

  • H7The proposal adapter fails or floods the verifier.needs 3 · reaches 4
    If it happens
    The case is stranded mid-run with no findings and no reviewer, or unchecked proposals reach the package.
    What stops it
    An adapter that raises or exceeds its budget forfeits every proposal, and the case still reaches the gate.
    What it still does not cover
    Bounds the blast radius of a bad proposer; it does not make the proposer trustworthy.
    Exercised by
    test_failing_proposal_adapter_forfeits_findings_and_reaches_the_gate

    severity 3exposure 2controllability 3class structuralfails closed

  • H8A displayed assurance figure outlives the code it measured.needs 3 · reaches 4
    If it happens
    The page asserts a level of verification that no longer corresponds to anything.
    What stops it
    The test count is recorded against a digest of the supplier sources and is withdrawn from the page when the digest stops matching.
    What it still does not cover
    Covers the supplier sources only. It detects a stale figure; it does not detect a test that passes for the wrong reason. It also fires only while the page is being built: a figure already published stays on the live site until the next deploy, so the digest bounds what a build may claim rather than what a deployed page still shows. Observed — adding five tests left the site displaying 71 against a suite of 78 until this deploy.
    Exercised by
    test_scenarios_are_reproducible_and_attributable

    severity 2exposure 2controllability 3class structuralfails closed
